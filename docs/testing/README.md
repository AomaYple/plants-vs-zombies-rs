# 测试策略

测试默认并行运行。只有共享外部状态、真实窗口、音频设备或平台生命周期测试无法隔离时，才对最小范围使用串行执行，并记录原因。

尽可能增加适用且有意义的测试类型，围绕实际接口、行为、错误分支和平台风险选择组合：

- 单元测试：纯函数、状态转换、数据校验和坐标变换。
- 集成测试：crate 边界、资源报告、命令/事件合同和回放。
- 回归测试：复现已修复缺陷，能在修复前失败、修复后通过。
- 边界/属性测试：空棋盘、最大实体、时间边界、路径大小写、损坏输入和重复命令。
- 确定性回放测试：固定初始状态、seed 和命令，核对状态摘要与事件序列。
- 资源解析与模糊测试：使用原创夹具验证有效、损坏和未知输入；按风险增加模糊测试，检查 panic、挂起及异常资源消耗。
- 平台契约测试：窗口尺寸、高 DPI、输入映射、存档介质和生命周期。
- 文档示例测试：验证公开 API 的可执行示例与实际接口一致。
- 端到端测试：验证完整用户流程；可自动化的部分自动执行，真实窗口、音频、Web 浏览器和移动设备另做实际运行验收，报告平台、版本和限制。

平台契约与运行验收覆盖 Windows、macOS、Linux、Web、Android 和 iOS 六个支持目标。桌面与 Web 先行，移动端随后接入；分别记录待实现、待验证和已验证状态。

测试不复制原版资源。公开夹具使用原创的最小数据；本机资源验证不得把原版载荷写入仓库。

尽可能提高有效测试覆盖率。实现后使用 `cargo llvm-cov` 报告测量范围与遗漏，持续补齐核心规则、边界条件、资源错误分支和跨平台契约；暂未覆盖的关键路径记录原因与补测安排。依据真实基线制定适用门槛，不能用无意义断言、排除关键代码或降低门槛制造通过。覆盖率不替代测试设计、性能基准和目标平台实际运行验收。
