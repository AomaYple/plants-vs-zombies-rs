# 测试策略

本文件记录测试的具体类型、隔离方法和验收细节；长期工程约束见 [工程原则](../principles/engineering.md)。

先明确被验证的合同，再选择能发现实际问题的断言。已明确行为优先测试先行；探索性探针用于获取证据，正式实现与交付前补齐适用测试，不把获取证据的顺序固定为所有任务必须遵循的流程。测试随实现交付，缺陷修复补充能捕获原缺陷的回归案例。

测试默认并行运行。每个测试独立使用临时目录、输入和状态，避免修改进程级环境变量、工作目录或依赖执行顺序。只有共享外部状态、真实窗口、音频设备或平台生命周期测试无法隔离时，才对最小范围使用串行执行，并记录原因；不要默认给整个 workspace 加 `--test-threads=1`。

验证优先全程在后台执行，避免抢焦点或切换前台。图形应用先尝试隐藏启动和目标窗口捕获，Web 优先使用隐藏浏览器；窗口不可观测、输入必须取得焦点等限制须明确记录，再决定必要的最小前台交互。后台捕获到无关窗口的画面不算目标应用证据，实际运行验收仍按对应平台合同完成。

尽可能增加适用且有意义的测试类型，围绕实际接口、行为、错误分支和平台风险选择组合：

- 单元测试：纯函数、状态转换、数据校验和坐标变换。
- 集成测试：crate 边界、资源报告、命令/事件合同和回放。
- 回归测试：复现已修复缺陷，能在修复前失败、修复后通过。
- 边界/属性测试：空棋盘、最大实体、时间边界、路径大小写、损坏输入和重复命令。
- 确定性回放测试：固定初始状态、seed 和命令，核对状态摘要与事件序列。
- 资源解析与模糊测试：使用原创夹具验证有效、损坏和未知输入；按风险增加模糊测试，检查 panic、挂起及异常资源消耗。
- 平台契约测试：窗口尺寸、高 DPI、输入映射、存档介质和生命周期。
- 文档示例测试：验证公开 API 的可执行示例与实际接口一致。
- 端到端测试：验证完整用户流程；可自动化的部分自动执行，真实窗口、音频、Web 浏览器和移动设备另做实际运行验收，报告平台、版本和限制。

平台契约与运行验收覆盖 Windows、macOS、Linux、Web、Android 和 iOS 六个支持目标。桌面与 Web 先行，移动端随后接入；分别记录待实现、待验证和已验证状态。

核心测试不需要窗口或原版资源。公开夹具使用原创的最小数据并记录来源；资源集成测试可读取清单登记的 `assets/original/`，无需再复制资源到夹具目录。CI 检查完整清单、文件指纹、路径大小写和文本格式；原版 EXE、截图、录像和存档的行为比对另在本机记录。

尽可能提高有效测试覆盖率。实现后使用 `cargo llvm-cov` 报告测量范围与遗漏，持续补齐核心规则、边界条件、资源错误分支和跨平台契约；暂未覆盖的关键路径记录原因与补测安排。依据真实基线制定适用门槛，不能用无意义断言、排除关键代码或降低门槛制造通过。覆盖率不替代测试设计、性能基准和目标平台实际运行验收。

发现测试预期或旧规则有误时，保留复现与参考证据，更新合同和测试，并对新预期建立回归保护。过时测试可以依据合同变化更新或移除；有效测试失败须解决原因。未执行的必要检查不算通过，平台证据分别记录受影响的已支持范围与尚待接入的目标。

## 覆盖率报告与当前状态

Windows CI 在现有实现检查 job 中顺序运行隐藏窗口的无资源/登记资源截图冒烟，复用已编译产物并设置每步 10 分钟上限。冒烟使用 Bevy 同步管线编译；原创探针截图检查右下角红蓝区域，夹具缺失或保存失败通过现有截图消费者返回非零退出。检查容许 GPU 色值差异，不执行整帧完全相等比对；它只验证最小实际绘制，不替代音频、设备输入、原版表现还原或其他平台验收。

方法文档维护统计合同，本批读数留在[版本化内容结果](../behavior/content-foundation-results.md)，历史快照留在 [平台探针结果](../behavior/platform-probe-results.md)和 [切片验收结果](../behavior/vertical-slice-results.md)，避免多份“当前覆盖率”漂移。报告至少写明代码状态、工具/版本、target、feature 组合、运行入口、命中行/总行与遗漏。

纯测试覆盖率与追加 native 窗口运行的覆盖率分别记录；追加 profile 必须来自同一次 instrumented 构建，并核对日志与实际画面。Web 条件代码不在 native 分母内，默认与 all-features 也不能互相代替。stable 行覆盖率没有启用分支统计时，不把 branch count 0 当作 100%。

版本化内容批次已取得默认和 all-features 的干净纯测试报告，没有追加窗口 profile；共享缓存混入旧 worktree 对象的探索报告保留，完整清理后重测，分母变化不作为覆盖率改善证据。此前切片的纯测试及同次 Windows 运行追加报告保留在[切片验收结果](../behavior/vertical-slice-results.md)。CLI stderr 闭管道、XML 显式空/缺省/CDATA/重复顺序、截图 30 秒最终退出和延迟音乐请求已有回归保护；新增内容严格失败、迁移回放和实际频率有独立回归。截图 observer/设备丢失、Web 条件路径、真实 DPR 2/4、触摸和未运行平台仍需针对性验收。自动测试保持并行，因共享 GPU/音频设备的窗口检查局部顺序执行。

覆盖率 CI 将默认和 all-features 拆为独立 job，各自生成 JSON/LCOV；这些 Linux 纯测试产物不包含本机 Windows 运行。cargo-llvm-cov 0.9.1 的 `report` 子命令实测拒绝 `--all-features`，feature 参数只传给插桩测试/运行命令，导出消费对应隔离 profile。stable 插桩本轮未统计 doctest，doctest 由常规 workspace 测试单独验证。尚未建立任意百分比硬门槛；后续补测继续以实际关键缺口为依据，不能把已有行覆盖率当作原版一致性或分支覆盖率。
