# ADR 0002：版本化原版参考资源

日期：2026-10-10。状态：已采纳。

## 问题

重写需要稳定的资源输入来开发资源解析、Reanim/粒子表现、音频接线和行为比对。仅依赖每台机器的外部目录会让清单、复现和 CI 检查缺少共同输入。项目需要把已确认的参考版本纳入仓库，同时保留它与新写代码的来源边界。

## 决定

维护者明确要求原版参考资源进入仓库。本决策取代 [ADR 0001](0001-repository-runtime-and-assets.md) 中将原版资源留在本机的决定；运行后端、重写范围、纯模拟分层及其余决定继续适用。

- 将当前核对过的参考资源导入 `assets/original/`，并将对应 `main.pak` 一并版本化。
- 使用 `assets/manifest.json` 记录相对路径、资源类型、来源大小、来源 SHA-256、导入后大小、导入后 SHA-256，以及文本格式规范化信息。
- 开发、CI 和平台打包共享清单登记的资源集合，移除原先的外部资源接入配置与无消费者的目录；部署介质由平台适配层处理，不规划运行时资源根目录覆盖接口。
- 资源包导入必须记录条目数、索引字节数和解包一致性；目录资源和 `main.pak` 必须逐文件、逐字节核对后才能成为同一参考基线。
- 文本资源只按仓库格式转换为 UTF-8、LF、无 BOM 并保留末尾换行；二进制资源保持原始字节。任何替换、重编码或重新解包都要重新生成清单并更新证据。
- 原版 EXE、截图、录像、存档和临时转换产物不进入资源目录；原版程序不作为重写运行时依赖。
- 项目原创代码、文档和原创测试数据使用 MIT；原版资源沿用独立的来源与许可说明，不纳入项目原创授权声明。

## 代价与影响

仓库体积会增加，克隆和 CI 资源校验需要额外时间；资源变更必须经过指纹核对，不能只依赖文件名或目录名。资源集成测试可以直接读取已登记输入，core 测试仍保持资源无关。跨平台路径大小写、资源包加载和许可证边界仍需要在实现阶段分别验收。

## 验证证据

当前基线包含 3,228 个解包条目，`main.pak` 的索引为 143,765 字节，解包文件总大小为 67,973,713 字节。包内条目与解包目录逐文件、逐字节一致；完整 SHA-256 和文本转换记录见 `assets/manifest.json`，EXE 与包的参考指纹见 [参考基线](../behavior/reference-baseline.md)。

## 重新评估

如果确认参考版本、资源包或导入转换发生变化，新增或更新清单与参考基线，并保留旧指纹和适用范围。不得静默覆盖历史基线，也不得把未登记资源、原版可执行文件或临时派生物混入版本化资源目录。
