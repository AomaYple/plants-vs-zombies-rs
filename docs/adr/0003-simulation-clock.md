# ADR 0003：使用显式可替换模拟时钟

## 状态

已采纳，2026-10-11。

## 背景

原版模拟 tick 时长和更新频率尚未通过本机运行测量确认。让核心规则读取墙钟或渲染帧率，会把平台调度差异混入行为结果，也无法稳定比较固定输入回放。

## 决策

`pvz-core` 使用 `SimulationClock` 保存当前 tick 和显式每秒 tick 数。`GameState::step` 只推进一个调用方提供的 tick；默认构造使用标记为开发参数的 60 tick/秒。时钟可以通过 `GameState::with_clock` 替换，核心不读取墙钟、不访问窗口或平台 API。

空棋盘阶段的 `DeterministicRng` 也只接受显式 seed，状态摘要包含 tick、阳光和 RNG 状态，事件顺序由规范化命令顺序决定。

## 代价与验证

这会要求表现层把渲染帧与模拟 tick 分开，并在原版时基测量完成后更新规则合同。确定性测试覆盖相同输入的状态摘要、命令排序、事件顺序和 RNG 向量；Criterion 基准记录空棋盘推进的可重复时间。

## 重新评估条件

如果原版测量表明时基需要分数 tick、变速或与输入采样绑定，新增兼容的时钟合同和回放版本，并保留当前开发参数的历史记录。
