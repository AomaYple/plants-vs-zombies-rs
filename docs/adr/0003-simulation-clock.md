# ADR 0003：使用显式可替换模拟时钟

## 状态

已采纳，2026-10-11。同步空棋盘 1.0 与开发切片 2.0 的实际合同，未确认原版时基。

## 背景

原版模拟 tick 时长和更新频率尚未通过本机运行测量确认。让核心规则读取墙钟或渲染帧率，会把平台调度差异混入行为结果，也无法稳定比较固定输入回放。

## 决策

`pvz-core` 使用 `SimulationClock` 保存当前 tick 和显式每秒 tick 数，核心不读取墙钟、不访问窗口或平台 API。空棋盘 `GameState::new/with_clock` 使用规则 1.0，`step` 每次推进一个 tick；`with_clock` 可替换时钟合同。

白天切片 `GameState::day` 使用规则 2.0 和明确标记的 60 tick/秒开发时钟。先按提交顺序处理命令，仅在本批没有重开、最终未暂停且局面仍运行时推进一个 tick。暂停、重开、终局和溢出处理见 [开发切片合同](../behavior/development-slice.md)，不把 `step` 调用次数直接当作实际推进 tick 数。

命令严格保持提交顺序，不按类型或金额排序；命令事件保留因果顺序，规则事件遵循显式开发阶段。`DeterministicRng` 封装锁定版本的 `oorandom::Rand64`，只接受显式 seed，摘要纳入完整内部状态。`StateDigest` 包括当前与初始合同、完整时钟、规则、实体、计时、ID、波次、暂停和终局；它不是持久存档/回放格式。

## 代价与验证

表现层须分离渲染、动画和模拟时钟。原版测量确认时基或规则后，同步规则版本、回归案例与兼容策略；当前没有持久回放消费者，不预建迁移器。

确定性测试覆盖相同输入的完整摘要、提交顺序、暂停/重开/终局、溢出拒绝、事件顺序和 RNG 向量。Criterion 分别记录空棋盘与切片的可重复时间，基准须说明调用次数、实际推进和输入规模。测试通过不证明与原版时基一致。

## 重新评估条件

如果原版测量表明时基需要分数 tick、变速或与输入采样绑定，新增兼容的时钟合同和回放版本，并保留当前开发参数的历史记录。
