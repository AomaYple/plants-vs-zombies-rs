# ADR 0001：仓库、运行层与资源边界

日期：2026-10-07。状态：部分已替代；资源公开边界由 [ADR 0002](0002-versioned-original-assets.md) 取代，运行后端由 [ADR 0004](0004-bevy-runtime.md) 取代；其余决定继续有效。本文保留当时的决策，当前阶段以 README 和路线图为准。

## 问题

制定本决策时，项目计划用 Rust 全量重写 Plants vs. Zombies，复用用户提供的原版素材作本机输入，以参考版本的可观察行为为还原目标，并将原创仓库公开到 GitHub。
当时只建立文档与结构，不写具体代码。本篇保留决策历史；当前资源方案以 ADR 0002 为准，阶段进度以 README 与路线图为准。

## 决定

- 仓库名 plants-vs-zombies-rs，展示标题统一为 Plants vs. Zombies — Rust 重写。
- 原创内容使用 MIT；原版参考资源的版本化方式当时决定留在本机，后由 ADR 0002 调整。
- Macroquad 作为运行与绘制层；纯 Rust 模拟内核与引擎解耦。
- 先预留 data、core、assets、app 和资产工具，待入口源码存在再注册 package。
- 固定 Rust 1.99.0、Edition 2024、resolver 3；启动实现时验证依赖和各目标兼容性。
- 桌面与 Web 先行；移动平台另设运行验收。
- 现有拆包的 3228 个文件与本机 main.pak 完全一致，先使用目录输入。
- 首阶段逻辑视口暂按 800 × 600 设计，原版实际视口与背景偏移待测量；正常模式在实际视口像素数绘制。
- 原版逻辑时基待测量；资源动画 fps 与模拟频率分别处理。

## 代价与替代方案

Macroquad 少了 Bevy 的 ECS、资源管线和调度工具；需要自己实现 Reanim、粒子、绘制顺序和资源装配。
Bevy 同样需要原版格式解析；其完整调度/ECS 架构目前未提供足够收益，故不采用。
未来更换后端仍会改写 app 内的 GPU、UI、输入和音频代码，不能承诺零成本迁移；core/data/CPU 资源模型可保留。

空 workspace 的 metadata 可验证，但 cargo check/test 没有 package 可执行。
当前 CI 明确只验证文档与结构；第一次注册 package 时同步启用真正的 Rust 质量门槛。

## 重新评估条件

出现仿射绘制能力、浏览器音频、移动生命周期、性能或打包的具体阻碍时，先做小型验证，再讨论替换相关后端。
发现参考 EXE 无法正确加载这组资源、或需改用另一个构建时，保留指纹记录并修订参考 ID。
依赖不支持固定工具链、或新平台需要更新编译器时，验证后通过 ADR 和 CI 一起升级。
