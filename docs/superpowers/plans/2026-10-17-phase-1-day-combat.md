# 第一阶段：完整白天战斗体验实施计划

> 执行说明：使用 `superpowers:executing-plans` 按依赖推进；阶段内部任务持续自动化验证，整批具备后集中实机测试与调整。

日期：2026-10-17
状态：计划已建立，游戏开发未启动；本次文档更新不构成以下任务已执行。

**目标：** 在现有白天单关中集中完成可靠战斗动作与反馈，统一控制状态，再通过 Windows/Web 实机修复与验收。

**架构：** core 提供真实战斗状态和有序事件，Runtime 维护模拟/表现时钟及事件消费，Scene 复用资源缓存与渲染池。表现不反向决定伤害、碰撞、移动、存活或胜负。

**工具链：** 使用仓库固定 Rust/Cargo/Bevy、现有测试/覆盖率/Criterion 和平台入口；版本以根配置为准。

**设计：** [阶段开发设计](../specs/2026-10-17-phased-development-design.md)与[七阶段总计划](2026-10-17-phased-development.md)。

## 范围与不变量

必做：普通僵尸行走/啃食/死亡，植物发射与受击/移除、投射物命中等必要反馈，现有音效与事件对应，暂停/恢复、双终局、重开、输入/UI，以及 B1 遗留验收。资源中有合适区段时复用；源语义不足时采用明确、可测的开发反馈并记录其边界。

本阶段不增加新植物/敌人种类、关卡进度、菜单存档、完整动画混合器、通用粒子系统或 MO3 播放器。现有规则 2.0、内容依据、RNG、命令顺序和已验证战斗结果是起点；新增观察信息的语义及事件兼容必须明确，不能假定事件扩展天然兼容。

开发任务完成后统一组织实机；CPU/Scene 测试和后台冒烟随开发运行。当前 B1 平台缺项不阻塞任务 1–4；只读状态和事件不足才是对应表现任务的直接前置。

## 任务 1：固定整批行为与可靠观察合同

**读取/按需求修改：** `crates/pvz-core/src/{world,events,zombies,plants,projectiles}.rs`、`crates/pvz-app/src/{runtime,render,resources,animation}.rs`、`docs/behavior/development-slice.md`；测试在 core 的 `tests/{determinism,vertical_slice}.rs` 和 app 的 `tests/{vertical_slice,presentation}.rs` 及已有模块测试。

**已有接口：** `GameState::step(&[Command]) -> StepEvents`、`GameState::state_digest()`、`StepEvents::as_slice()`、`Runtime::{input,advance,take_events}`、`Scene::update`。目前 `Damaged { target, remaining }` 不携带攻击者，`ZombieDied { id }` 不携带死亡位置；不能凭距离、受伤目标或上一帧位置猜测。

- [ ] 固定正常/失败两份现有内容的命令场景：行走接近、啃食、目标被铲除/被吃掉、多个攻击者、投射物击杀、割草机击杀、同 tick 多事件、暂停、终局和重开。
- [ ] 在实际模拟判定点确定只读攻击者/目标和精确死亡锚点的最小输出，写明产生/结束时机、同 tick 顺序、消费与清理方式；在实现前将具体类型/签名及兼容决定写入本节和开发切片合同。
- [ ] 明确摘要、事件和版本策略：表现查询不得改变状态或 RNG；观察输出若扩展公开事件，保留既有投影顺序并显式测试新完整序列，按实际影响更新版本/兼容或拒绝策略。
- [ ] 为上述场景补能捕获缺失合同的回归，实现在 core 判定点生成可靠输入；核对同条件战斗状态和原有事件投影，不能只比较最终胜负。

**产出：** 后续表现可直接消费的状态/事件合同、回归和兼容说明；该任务的通过只代表阶段内部工程进展。

## 任务 2：集中实现动作与资源消费

**修改：** `crates/pvz-app/src/{resources,animation,render,runtime}.rs`；解析存在真实缺口才涉及 `crates/pvz-assets/src/reanim.rs`。测试复用 app `tests/presentation.rs`、`resources.rs`/`render.rs` 等模块内测试与原创夹具。

**输入/输出：** 消费任务 1 的观察合同和现有 `PreparedAnimation`、`LoadedResources`、渲染池；输出能表达行走、啃食、死亡与必要植物/命中反馈的 Scene。动作生命周期与模拟实体生命周期分开。

- [ ] 核对本阶段实际用到的 marker、轨道、图像及来源清单，明确每个动作的起止、循环或一次播放和中断规则；缺图或不支持语义按已有错误边界报告。
- [ ] 先为动作切换、多个对象、空/短轨道、最后一帧、透明度/层序、相位及移除清理建立原创夹具和真实 Scene 断言，再接入缓存与绘制。
- [ ] 完成普通僵尸行走转啃食、目标失效恢复行走、死亡表现与残留清理；死亡锚点消费任务 1 的精确快照。
- [ ] 集中补齐现有植物发射/受击/移除及投射物命中的必要可见反馈；只接本阶段消费者，不预建全播放器或特效框架。
- [ ] 检查资源一次加载/prepare 与池复用，禁止每帧重新解析、全量解码/上传；回归向日葵 idle 及已有静态对象。
