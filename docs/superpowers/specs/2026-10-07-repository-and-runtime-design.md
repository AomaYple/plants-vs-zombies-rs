# Plants vs. Zombies — Rust Reimplementation 设计

## 状态与目标

状态：文档、结构与参考资源已落地，Rust 实现待用户明确授权；2026-10-07 写入，2026-10-10 更新资源方案。本文维护模块方案，长期约束见 [项目原则](../../principles/README.md)，具体任务与验收见实施计划和贡献指南，不代表游戏已经实现。

目标是建设一个将来可公开的 Cargo workspace，使用 Rust 全量重写游戏逻辑和运行系统，采用 Macroquad 作为首个运行/绘制后端，优先覆盖 Windows、Linux、macOS 和 Web，并在后续接入 Android 与 iOS。

原版程序不作为实现依赖。版本化参考资源位于 `assets/original/`，由清单记录来源和指纹；公开仓库不包含原版 EXE、截图、录像、存档或未登记的临时派生包。

## 已确认输入

参考基线写在 `docs/behavior/reference-baseline.md`。本机 EXE 和 `main.pak` 的文件指纹已经记录，现有 3228 个原始解包文件与包内内容逐字节一致。仓库导入时规范化 290 个文本资源的编码与换行，原始和导入后指纹分别登记在 `assets/manifest.json`。EXE 版本字段为 `1.2.0.1073`，路径名称仍显示 `1.1.0.1056`，因此使用文件指纹标识基线，并把版本标签差异保留为风险记录。

目前确认的资源事实包括标题图 800×600、若干背景图 1400×600、SeedBank 446×87，以及 PeaShooter/Zombie Reanim 文件的 12 fps 资源值。原版逻辑 tick、完整画布滚动、碰撞盒和规则顺序待运行观测。

## 仓库布局

```text
crates/               未来的 pvz-data、pvz-core、pvz-assets、pvz-app
tools/pvz-asset-tool/ 本地资源审计和转换 CLI
assets/               版本化参考资源与清单
tests/                自制夹具、回放和跨平台契约
docs/                 设计、计划、行为证据、ADR
.github/              CI、Issue 模板、PR 模板
```

仓库基线阶段的 Cargo workspace 使用空 `members` 列表，只验证元数据和配置，不伪造缺失的 package。开始编写 package 时，以一项可独立测试的工作为单位注册成员、生成 `Cargo.lock` 并更新 CI。

## 模块与依赖

### `pvz-data`

存放内部实体 ID、植物/僵尸/投射物/地形/波次/关卡的版本化数据结构，以及不依赖引擎的数据校验。它不能读文件、访问资源、创建窗口或决定操作系统路径。

### `pvz-core`

提供纯模拟：棋盘、植物、僵尸、投射物、阳光、割草机、状态机、碰撞、固定时间推进、确定性 RNG、逻辑事件和回放。它接收抽象的逻辑命令，返回状态和事件；不播放音频、不绘制纹理、不读取墙钟、不读资产。

模拟步长暂不写死为原版 60 Hz。`SimulationClock` 基础可使用明确标记、可替换的开发参数；作为原版时基使用或验收前完成行为测量。渲染帧率、资源动画 fps 和模拟 tick 分开；相关资源中的 12 fps 作为动画采样输入，实际播放器语义仍需验证。

### `pvz-assets`

提供资源 ID、目录/包输入接口、`resources.xml` 清单解析、PNG/JPEG/OGG 元数据、Reanim 轨道模型和粒子 XML 的受支持子集。它输出 CPU 侧资源模型和诊断；不能修改 core 的生命值、伤害或波次。

内部接口保持抽象，例如 `AssetProvider::load_image/load_animation/load_particle/load_sound/load_text`；应用加载仓库清单登记的资源，目录、浏览器与移动端打包介质由平台适配层提供字节。原创占位资源只用于显式的诊断和隔离测试。`main.pak` 读取与可重建的转换缓存按实测需求后续引入，不是 core 的依赖。

### `pvz-app`

作为 Macroquad 入口，负责平台窗口、逻辑坐标到视口坐标映射、鼠标/触摸归一化、资源装配、动画采样、纹理绘制、粒子、音频、存档和生命周期。它通过 core 的命令和事件接线，不能复制一套隐藏规则。

逻辑视口暂按 800×600 设计，需先核实参考版本。实际窗口保持纵横比，通常使用 `scale = min(window_width / logical_width, window_height / logical_height)`，并保存 offset 做输入反变换。1400×600 场景背景不能盲目压进 800×600；背景裁剪和滚动必须以参考行为为准。

正常高分辨率模式在实际视口像素数绘制，避免将低分辨率整帧放大导致 UI/文字模糊；经典像素模式可作为独立选项。高清替代图只改变表现资源，不改变逻辑坐标和碰撞盒。

### `pvz-asset-tool`

宿主机 CLI 在仓库根目录读取 `assets/manifest.json` 及其登记资源，输出检查报告；图集等可重建的转换缓存写入被忽略的 `target/`。报告绝对路径时默认脱敏；输入素材保持只读，原版可执行文件和未登记临时文件不会被复制到仓库或 CI。运行时不规划资源根目录覆盖接口，平台部署读取同一版本化资源集合。

## 模拟与表现合同

每次更新接收按序的输入命令，推进固定时间，生成事件。渲染使用状态快照和事件消费，不通过动画帧决定伤害。暂停时冻结模拟和可冻结的表现时钟，应用切后台时走显式生命周期事件。

确定性回放包括 schema 版本、规则版本、参考基线 ID、模拟时钟、RNG 算法/seed、初始状态和带 tick 序号的命令。core 测试比较状态摘要与事件序列；不比较纹理像素，不要求重写与原版使用相同随机算法。

## 资源和许可边界

公开仓库使用 MIT 许可证只授权本项目原创代码、文档和明确原创的测试数据。版本化参考资源由 `assets/manifest.json` 记录来源与导入处理，保留独立的资源来源和许可边界；发布前检查 Git 历史、清单、缓存、临时派生物和构建产物。

## 错误处理

资源解析遇到缺失、大小写冲突、编码错误、未知轨道或格式版本时返回带路径和上下文的诊断；仓库资源缺失或损坏时显式失败，不静默改用占位素材。游戏运行时资源缺失显示可读错误状态，核心模拟仍可在无资源测试环境运行。

跨平台失败按层报告：core 错误、资源诊断、平台 I/O、音频/图形能力和打包环境分别记录。平台支持必须有目标平台构建和最小运行证据，不能仅凭 crate 能编译宣称支持。

## 测试策略

- core：纯单元测试、属性/边界测试、固定种子回放和事件顺序测试。
- data：schema 版本、范围和互斥约束测试。
- assets：原创小夹具的成功/失败解析、路径归一化、大小写冲突和确定性报告测试。
- app：窗口/输入变换和资源装配的契约测试；需要真实窗口的验证标为手工平台测试。
- CI：校验版本化资源清单、文件指纹与文本格式；core 测试保持资源无关，资源集成测试可读取登记的参考资源。package 注册后执行对应格式、检查、测试、Clippy、文档、依赖策略与构建矩阵。

## 交付顺序

用户授权实现后，按实施计划先建立 data/core 最小基础，再接入资源审计与视口探针。第一可玩垂直切片是白天 5×9 草坪、向日葵、豌豆射手、普通僵尸、阳光、豌豆、一次固定波次、割草机、胜负、暂停和重开。完整模式、UI、存档和移动端均依赖该切片的确定性合同稳定。
