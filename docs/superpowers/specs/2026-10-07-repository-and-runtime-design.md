# Plants vs. Zombies — Rust 重写设计

## 状态与目标

本文维护当前架构与后续方向。基础设施、白天内容数据化与静态切片的工程验收和独立复核属于已记录的历史批次；S1 与 S2-A 已交付，本地 B1 已接入普通僵尸 walk，完整平台验收与 Git/CI 尚未闭合。B1 冻结源码的旧检查保留范围，仓库维护后的新验证和匹配平台包仍须核验；原版规则、完整动态表现与其他平台运行继续待验。历史入口见[基础与切片计划](../plans/2026-10-07-foundation-and-asset-audit.md)，当前任务见[总计划](../plans/2026-10-13-minimum-playable-vertical-slices.md)，原版证据见[专题计划](../plans/2026-10-12-reference-behavior-measurement.md)，各批实测见[增量结果](../../behavior/content-foundation-results.md)与[静态切片历史](../../behavior/vertical-slice-results.md)，长期约束见[项目原则](../../principles/README.md)。

目标是建设包含版本化参考资源的 Cargo workspace，使用 Rust 全量重写游戏逻辑和运行系统，采用 Bevy 作为运行/绘制后端，优先覆盖 Windows、Linux、macOS 和 Web，并在后续接入 Android 与 iOS。

原版程序不作为实现依赖。版本化参考资源位于 `assets/original/`，由清单记录来源和指纹；公开仓库不包含原版 EXE、截图、录像、存档或未登记的临时派生包。

## 已确认输入

参考基线写在 `docs/behavior/reference-baseline.md`。本机 EXE 和 `main.pak` 的文件指纹已经记录，现有 3228 个原始解包文件与包内内容逐字节一致。仓库导入时规范化 290 个文本资源的编码与换行，原始和导入后指纹分别登记在 `assets/manifest.json`。EXE 版本字段为 `1.2.0.1073`，路径名称仍显示 `1.1.0.1056`，因此使用文件指纹标识基线，并把版本标签差异保留为风险记录。

目前确认的资源事实包括标题图 800×600、若干背景图 1400×600、SeedBank 446×87，以及 PeaShooter/Zombie Reanim 文件的 12 fps 资源值。原版逻辑 tick、完整画布滚动、碰撞盒和规则顺序待运行观测。

## 模块与依赖

### `pvz-data`

当前提供强类型 ID、schema 与规则版本、参考基线 ID、严格白天关卡 DTO 和序列化合同；`DayLevelDefinition`、`DayRulesDefinition`、`DaySpawnDefinition` 与 `ContentBasis` 表达已消费的原创内容格式，拒绝未知、遗漏与重复字段。它不读文件、访问资源、创建窗口或决定操作系统路径；规则有效性与支持版本由 core 判断。完整植物/僵尸/投射物/地形/关卡 schema 按实际内容消费者扩展，当前实体模型位于 core，不预建无消费者模型。

### `pvz-core`

当前提供空棋盘规则 1.0 和白天开发切片规则 2.0：棋盘、植物、僵尸、投射物、阳光、割草机、碰撞、固定时间推进、确定性 RNG、逻辑命令、事件和状态摘要。固定输入回放由测试验证，持久回放格式尚未实现。它不播放音频、不绘制纹理、不读取墙钟、不读资产。

模拟步长暂不写死为原版 60 Hz。`SimulationClock` 基础可使用明确标记、可替换的开发参数；作为原版时基使用或验收前完成行为测量。渲染帧率、资源动画 fps 和模拟 tick 分开；相关资源中的 12 fps 作为动画采样输入，实际播放器语义仍需验证。

### `pvz-assets`

当前提供仓库 JSON 清单、资源索引/指纹审计、Reanim 轨道与粒子 XML 受支持子集，输出 CPU 模型和诊断；不能修改 core 的生命值、伤害或波次。纯解析接口接收字节或文本，宿主目录审计通过显式 `AssetRoot` 入口读取。

应用层提供 native/Web 字节加载、图像/OGG 解码和引擎装配；移动端介质待接入。`resources.xml` 通用资源管理、`main.pak` 读取与可重建转换缓存按实际需求引入，当前没有这些通用 API。原创占位资源只用于显式诊断和隔离测试。

### `pvz-app`

当前 Bevy 入口负责窗口、视口/输入映射、native/Web 资源装配、向日葵动态 idle、本地普通僵尸开发 walk、其余静态构图、中文切片 UI、事件音效及音频探针；纯模块提供动画采样与仿射/裁剪合同。正常内容由编译时嵌入的严格原创 JSON 解析后交给 core 纯装配，Runtime 消费实际模拟频率。共享缓存、全局表现相位和离散循环是开发合同，原版动作选择、插值、混合与切换时机仍未知。可靠啃食/死亡反馈、完整动画混合、原版粒子、存档和移动生命周期尚未接入；表现通过 core 的命令和事件接线，不能复制隐藏规则。

逻辑视口暂按 800×600 设计，需先核实参考版本。实际窗口保持纵横比，通常使用 `scale = min(window_width / logical_width, window_height / logical_height)`，并保存 offset 做输入反变换。1400×600 场景背景不能盲目压进 800×600；背景裁剪和滚动必须以参考行为为准。

正常高分辨率模式在实际视口像素数绘制，避免将低分辨率整帧放大导致 UI/文字模糊；经典像素模式可作为独立选项。高清替代图只改变表现资源，不改变逻辑坐标和碰撞盒。

### `pvz-asset-tool`

当前宿主机 CLI 在仓库根目录读取 `assets/manifest.json` 及登记资源，提供 `audit` 报告和 `inspect-reanim` 动画概要；没有转换与打包命令。以后引入图集等转换时，可重建缓存写入被忽略的 `target/`。诊断绝对路径默认脱敏；输入素材保持只读。CLI 没有资源根覆盖参数，平台部署读取同一版本化资源集合。

## 模拟与表现合同

模拟接收严格按提交顺序的命令；空棋盘每次 `step` 推进一个 tick。切片先处理命令，仅在本批无重开、最终未暂停且局面运行时推进，暂停/重开/终局合同见 [开发切片合同](../../behavior/development-slice.md)。渲染消费状态与事件，不通过动画帧决定伤害。暂停冻结模拟和可冻结的表现时钟；完整切后台生命周期适配待接入。

确定性测试固定规则版本、模拟时钟、RNG 算法/seed、初始状态与命令顺序，比较完整状态摘要和事件序列；不比较纹理像素，也不要求采用原版随机算法。后续持久回放须携带 schema、规则与参考基线版本及带 tick 序号的命令，具体格式按实际消费者引入。

## 资源和许可边界

公开仓库使用 MIT 许可证只授权本项目原创代码、文档和明确原创的测试数据。版本化参考资源由 `assets/manifest.json` 记录来源与导入处理，保留独立的资源来源和许可边界；发布前检查 Git 历史、清单、缓存、临时派生物和构建产物。

## 错误处理

缺失资源、大小写冲突、编码错误、不支持的格式版本与影响解释的未知语义返回带上下文的诊断；已确认的扩展处理遵循具体解析合同。仓库资源缺失或损坏时显示中文错误，不静默改用占位素材；核心模拟仍可在无资源环境测试。

跨平台失败按层报告：core 错误、资源诊断、平台 I/O、音频/图形能力和打包环境分别记录。平台支持必须有目标平台构建和最小运行证据，不能仅凭 crate 能编译宣称支持。

## 测试策略

- core：纯单元测试、属性/边界测试、固定种子回放和事件顺序测试。
- data：schema 版本、范围和互斥约束测试。
- assets：原创小夹具的成功/失败解析、路径归一化、大小写冲突和确定性报告测试。
- app：窗口/输入变换和资源装配的契约测试；需要真实窗口的验证标为手工平台测试。
- CI：校验版本化资源清单、文件指纹与文本格式；core 测试保持资源无关，资源集成测试可读取登记的参考资源。package 注册后执行对应格式、检查、测试、Clippy、文档、依赖策略与构建矩阵。
