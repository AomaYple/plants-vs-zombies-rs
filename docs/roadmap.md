# 项目路线图

当前产品入口是[阶段性最小可玩垂直切片总计划](superpowers/plans/2026-10-13-minimum-playable-vertical-slices.md)。每个阶段和独立子阶段都必须从正常入口开始，包含玩家操作、可观察结果、胜利/失败（适用时）以及重试或返回路径，并保留此前可玩流程。正确性优先；测试、构建、平台运行和原版行为证据分别记录。

截至 2026-10-16，主线已完成规则和仓库卫生整合，并合入测试反馈优化。S2-B1 的源码与工程检查已完成，但其平台验收仍未闭合；本轮不把维护提交、CI 或开发参数升级为完整阶段完成。

## 可玩阶段

| 阶段 | 交付合同 | 状态 |
| --- | --- | --- |
| S0 历史起点 | 白天静态切片中的种植、收阳光、防守和指定胜利流程 | 已交付历史范围 |
| S1 可靠白天单关 | 正常胜利/失败、终局冻结、暂停/恢复、重开和再种植 | 已完成开发闭环 |
| S2 动态白天单关 | 在同一关卡接入向日葵 idle、僵尸动作和后续反馈 | S2-A 已交付；S2-B1 工程实现已完成，平台验收待完成；B2 未开始 |
| S3 两关白天冒险 | 新策略、选卡、两关解锁、保存并继续 | 待开始 |
| S4 四种环境关卡 | 夜间、泳池、雾、屋顶各一条可玩关卡 | 待开始 |
| S5 冒险通关闭环 | 从已有进度到最终遭遇、通关或失败重试 | 待开始 |
| S6 附加模式 | 保龄球、生存、砸罐子、花园、图鉴/商店各一条闭环 | 待开始 |
| S7 移动可玩关卡 | Android/iOS 触摸、生命周期、保存/继续和音频 | 待验 |
| S8 原版内容补齐 | 在可玩版本上逐批补角色、关卡、模式、动画、粒子和音乐 | 待开始 |
| S9 六平台发布 | 安装/打开部署包、游玩、保存、重启恢复 | 待开始 |

远期阶段不是立即实施的文件清单。启动下一阶段时，依据实际前置、现有消费者和平台风险细化任务，不预建没有验收入口的全集 schema、框架或 package。

## 当前下一步

1. 补齐 S2-B1 Windows 正常窗口的无遮挡身体动态图、失败冻结和 resize 证据。
2. 补齐 Web 操作后的 warn/error 诊断查询，并保持浏览器、设备音频和截图比较的限制说明。
3. 完成 macOS/Linux 目标窗口复核；从 S3 开始做 Android/iOS 构建和启动探针。
4. 在可靠的 core 输入、攻击者识别和死亡事件合同确定后，单独设计 S2-B2 啃食/死亡反馈。
5. 原版 `tutorial-plant-01` 继续以三次有效重复为门槛；当前为 `0/3`，开发参数不能直接升级为原版规则。

## 横向证据和平台

原版身份、资源和已核对事实由[参考基线](behavior/reference-baseline.md)维护；测量方法和采纳条件由[行为测量专题计划](superpowers/plans/2026-10-12-reference-behavior-measurement.md)维护。窗口阻塞只影响直接依赖它的规则采纳，独立开发按开发合同继续。

| 平台 | 当前证据 | 仍需补齐 |
| --- | --- | --- |
| Windows | S1/S2-A 正常路径、当前构建和后台冒烟；S2-B1 工程检查通过 | B1 正常窗口动态图/失败冻结/resize；设备音频、后续关卡和安装包 |
| Web | default/probe 构建、绑定和部分正常输入/终局/暂停/重开记录 | 当前操作后的完整诊断、真实 DPR 2/4、触摸、更多浏览器、设备音频和部署包 |
| macOS/Linux | CI 构建、测试和静态检查 | 目标窗口和后续平台路径 |
| Android/iOS | 平台无关 core 合同 | S3 开始探针；S7 完成触摸、生命周期、存储、音频和实机/目标环境闭环 |
