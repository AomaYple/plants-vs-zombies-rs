# 项目路线图

路线按可独立验证的交付阶段排列，具体任务顺序见 [实施计划](superpowers/plans/2026-10-07-foundation-and-asset-audit.md)。长期约束见 [项目原则](principles/README.md)，提交验收见 [贡献指南](../CONTRIBUTING.md)。

跨平台支持目标包含 Windows、macOS、Linux、Web、Android 和 iOS。桌面与 Web 先行，移动端随后接入；所有平台均须分别完成构建与最小运行验收。

## P0：参考基线与仓库基线

- [x] 记录 EXE/main.pak 指纹和版本字段差异。
- [x] 逐文件核对 main.pak 与现有解包目录。
- [x] 落地公开仓库边界、MIT、忽略规则、目录和文档。
- [ ] 由用户审阅文档并确认开始写实现。

## P1：资源审计工具

- [ ] 按实施计划先完成 `pvz-data` 和可配置的 `pvz-core` 最小基础；开发参数明确标记，作为原版时基验收前完成对应测量。
- [ ] 注册 `pvz-assets` 与 `pvz-asset-tool` package。
- [ ] 解析资源清单并输出缺失/未引用/大小写冲突报告。
- [ ] 解析 Reanim 的最小数据模型和粒子 XML 的最小数据模型。
- [ ] 使用原创格式夹具完成错误、路径、编码和确定性报告测试。

## P2：窗口与渲染探针

- [ ] 注册 `pvz-app` package，使用 P1 已建立的数据与模拟基础。
- [ ] Macroquad 启动窗口、逻辑视口和输入坐标反变换。
- [ ] 用占位图渲染背景、精灵层、透明度、旋转和裁剪。
- [ ] 在 Windows、Linux、macOS 和 Web 通过最小启动检查。

## P3：核心垂直切片

- [ ] 扩展 P1 的模拟基础，核对固定 tick、命令、事件、RNG 与回放合同。
- [ ] 实现 5×9 白天草坪、阳光、向日葵、豌豆射手、普通僵尸、豌豆、割草机。
- [ ] 固定输入回放验证种植、产阳光、投射物命中、啃食、胜负、暂停和重开。
- [ ] 接入资源表现层，不允许表现层反向改变规则。

## P4：规则与内容

- [ ] 把植物、僵尸、投射物、地形和波次迁移到版本化数据。
- [ ] 按行为证据逐类加入护甲、减速、特殊攻击、泳池、夜间、雾和屋顶。
- [ ] 完成 Reanim 常用轨道、粒子子集、音频事件和资源缓存。

## P5：完整流程

- [ ] 主菜单、冒险进度、选卡、图鉴、商店、小游戏、生存、谜题、禅境花园。
- [ ] 跨平台存档、设置、暂停恢复和错误报告。
- [ ] 逐模式建立无资源 core 测试和本机表现验收。

## P6：平台发布准备

- [ ] 桌面三平台打包和资源安装路径。
- [ ] WebAssembly 浏览器资源加载、输入、音频手势和 IndexedDB/LocalStorage 存档。
- [ ] Android 触摸、生命周期和应用数据目录。
- [ ] iOS 在 macOS/Xcode 环境验证签名、生命周期、触摸和资源包。
- [ ] 公开发布前扫描跟踪文件、许可证、商标、素材和构建产物。

## 横向质量门槛

每个阶段执行工程原则与游戏开发原则，本节只跟踪贯穿阶段的交付事项：

- [ ] 首次 package 同时提交锁文件、继承 lint、更新阶段文档并启用适用 CI；质量检查从对应实现开始。
- [ ] 相关实现已有正确性测试、覆盖率报告和热路径基准，核心回放与平台合同随变更验证。
- [ ] 优化前后有同条件性能测量与行为证据；开发流程持续减少重复工作和反馈等待。
- [ ] 六个平台分别记录构建、运行、限制与未验证项，公共仓库和发行产物通过资源与许可核对。
