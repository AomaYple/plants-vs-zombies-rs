# 项目路线图

路线按“每阶段可独立验证”排列，长期约束见 [项目原则](principles/README.md)。阶段完成不等于资源获准公开；所有原版资源验收在本机进行。

跨平台支持目标包含 Windows、macOS、Linux、Web、Android 和 iOS。桌面与 Web 先行，移动端随后接入；所有平台均须分别完成构建与最小运行验收。

## P0：参考基线与仓库基线

- [x] 记录 EXE/main.pak 指纹和版本字段差异。
- [x] 逐文件核对 main.pak 与现有解包目录。
- [x] 落地公开仓库边界、MIT、忽略规则、目录和文档。
- [ ] 由用户审阅文档并确认开始写实现。

## P1：资源审计工具

- [ ] 注册 `pvz-assets` 与 `pvz-asset-tool` package。
- [ ] 解析资源清单并输出缺失/未引用/大小写冲突报告。
- [ ] 解析 Reanim 的最小数据模型和粒子 XML 的最小数据模型。
- [ ] 使用原创格式夹具完成错误、路径、编码和确定性报告测试。

## P2：窗口与渲染探针

- [ ] 注册 `pvz-app` 与 `pvz-data` package。
- [ ] Macroquad 启动窗口、逻辑视口和输入坐标反变换。
- [ ] 用占位图渲染背景、精灵层、透明度、旋转和裁剪。
- [ ] 在 Windows、Linux、macOS 和 Web 通过最小启动检查。

## P3：核心垂直切片

- [ ] 注册 `pvz-core`，完成固定 tick、命令、事件、RNG 和回放 schema。
- [ ] 实现 5×9 白天草坪、阳光、向日葵、豌豆射手、普通僵尸、豌豆、割草机。
- [ ] 固定输入回放验证种植、产阳光、投射物命中、啃食、胜负、暂停和重开。
- [ ] 接入资源表现层，不允许表现层反向改变规则。

## P4：规则与内容

- [ ] 把植物、僵尸、投射物、地形和波次迁移到版本化数据。
- [ ] 按行为证据逐类加入护甲、减速、特殊攻击、泳池、夜间、雾和屋顶。
- [ ] 完成 Reanim 常用轨道、粒子子集、音频事件和资源缓存。

## P5：完整流程

- [ ] 主菜单、冒险进度、选卡、图鉴、商店、小游戏、生存、谜题、禅境花园。
- [ ] 跨平台存档、设置、暂停恢复和错误报告。
- [ ] 逐模式建立无资源 core 测试和本机表现验收。

## P6：平台发布准备

- [ ] 桌面三平台打包和资源安装路径。
- [ ] WebAssembly 浏览器资源加载、输入、音频手势和 IndexedDB/LocalStorage 存档。
- [ ] Android 触摸、生命周期和应用数据目录。
- [ ] iOS 在 macOS/Xcode 环境验证签名、生命周期、触摸和资源包。
- [ ] 公开发布前扫描跟踪文件、许可证、商标、素材和构建产物。

## 横向质量门槛

- [ ] 所有可读文本文件通过 UTF-8/LF/无 BOM 检查；新增二进制文件必须有明确用途和许可记录。
- [ ] 尽可能增加适用且有意义的单元、集成、回归、边界/属性、确定性回放、资源解析、平台契约、文档示例和端到端测试；解析器按风险补充模糊测试，测试默认并行。
- [ ] 尽可能提高有效测试覆盖率，报告测量范围与遗漏，持续补齐关键路径和错误分支；暂未覆盖的关键路径记录原因与补测安排。
- [ ] Windows、macOS、Linux、Web、Android 和 iOS 分别有目标平台构建与最小运行证据，明确尚未实现或验证的部分。
- [ ] 核心规则和资源热路径都有可重复的 Criterion 性能基准，并记录优化前后结果。
- [ ] 不保留死代码或未使用项；按受支持的 target/feature 组合运行编译器/Clippy，并核对实际调用方；提交前删除无用途文件和过时配置。
- [ ] Git 提交遵循 Conventional Commits，每次聚焦一个可审阅的变更；提交说明和正文使用中文，type/scope 与技术名称保留标准写法。
- [ ] 正确性测试通过后才允许性能优化；优化后必须重跑行为、回放和性能验证。
