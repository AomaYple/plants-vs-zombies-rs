# 项目原则

本目录集中维护项目的长期原则，分为两类：

- [工程原则](engineering.md)：说明项目如何开发、测试、验证、维护和交付。
- [游戏开发原则](game-development.md)：说明如何还原原版行为、组织运行时、接入平台并提高游戏开发效率。

## 共同原则

- **正确性第一、速度第二、内存第三**：以参考行为、明确合同和边界条件判断正确性，保留必要的测试、行为核对与平台验收。发现实现、测试或旧结论有误时依据证据纠正，不能把已有测试通过当作结论永远正确。
- **速度包含运行与开发迭代**：尽可能提高游戏与工具的运行速度、降低延迟，并缩短游戏开发、构建、测试、验证与迭代周期。满足正确性、必要质量门槛与目标平台资源约束后，速度与内存存在取舍时优先满足速度目标，再改善内存占用；记录目标负载、测量结果和内存代价。具体优化顺序由实测瓶颈决定，可以同时改善速度与内存。
- **以证据判断结果**：区分规划、静态检查、构建、测试、实际运行和原版行为比对；结论附来源与适用范围，未验证的功能、参数、工具和平台明确标记。

同一条长期规则在对应原则文档维护，入口保留必要摘要，方法和命令通过链接引用。配置声明实际工具链与 lint，CI 声明实际执行的检查；发现它们与原则不符时应修正并验证，不能把配置缺项当作放宽原则的依据。

规则应说明目的、适用范围与可检查的结果；不把特定开发顺序或工具偏好扩大为所有变更的强制要求。根据合同、风险或测量证据更新规则，合并重复项、删除失效项，保留原始证据和决策记录；不能为了让失败通过而改写验收条件。

更新规则时同步受影响的摘要、命令、计划与配置。执行指令仍遵循适用指令的优先级与作用域；本索引规定文档职责，不另设指令优先级。
