# 项目原则

本目录集中维护长期有效的项目规则，分为两类：

- [工程原则](engineering.md)：项目如何开发、测试、验证、维护和交付。
- [游戏开发原则](game-development.md)：如何还原原版行为、组织运行时、接入平台和提高开发效率。

## 共同原则

- **正确性第一、速度第二、内存第三**：以参考行为、明确合同和边界条件判断正确性；保留必要的测试、行为核对和平台验收。发现实现、测试或旧结论有误时依据证据纠正，不能把测试通过当作永远正确。
- **速度包含运行与开发迭代**：满足正确性、必要质量门槛和目标平台资源约束后，缩短运行、构建、测试、验证和返工等待。速度与内存存在取舍时记录目标负载、测量结果和代价；没有同条件证据只记录读数，不改变默认调度。
- **以证据判断结果**：区分计划、静态检查、构建、测试、实际运行、平台玩家验收和原版行为比对；结论附来源、范围和限制，未验证项目明确标记。

同一条长期规则只在对应原则文档完整维护，入口和方法页保留必要摘要与链接。配置、CI 和脚本描述实际执行的工具与门槛；发现不一致时修正并验证，不能把配置缺项当作放宽原则的依据。

规则必须说明目的、适用范围和可检查结果。根据合同、风险和测量证据合并重复项、删除失效项，保留原始证据和决策记录；不能为了让失败通过而改写验收条件。公开文档不得依赖被忽略的 .superpowers/、个人路径或临时产物；历史结果只修正明确的导航/事实错误，不把后续验证回写成当时已完成。
