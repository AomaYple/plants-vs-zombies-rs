# 项目原则

本目录把项目的长期原则分为两类：

- [工程原则](engineering.md)：说明项目如何开发、测试、验证、维护和交付。
- [游戏开发原则](game-development.md)：说明这个 PvZ Rust 重写如何设计、还原行为、组织运行时并接入平台。

两类原则共同遵守正确性优先、证据优先和如实报告的要求。原则描述稳定约束；当前进度放在 [路线图](../roadmap.md)，模块接口放在 [架构文档](../architecture/README.md)，测试和性能细节分别放在 [测试策略](../testing/README.md) 与 [性能策略](../performance/README.md)。

文档职责按以下层次维护：

```text
全局 AGENTS.md       通用协作、授权、安全和验证原则
项目 AGENTS.md       代理需要快速读取的项目边界与硬约束
本目录               工程原则与游戏开发原则的稳定定义
CONTRIBUTING.md      贡献流程、命令和提交验收步骤
专题文档             架构、行为、测试、性能和资源的具体证据与方法
```

更新原则时，同时检查项目 `AGENTS.md`、`CONTRIBUTING.md`、README 和受影响专题文档中的摘要与链接，避免出现相互矛盾的规则。计划中的功能、平台和工具只有在对应证据完成后，才能写成已支持或已可用。
