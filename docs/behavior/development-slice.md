# 白天可玩切片开发合同 2.0

这是原创开发规则与内部确定性合同，不是原版还原报告。原版窗口观测尚未取得有效画面，参考模拟频率、时间间隔、碰撞与事件阶段顺序仍待受控重复测量。不得把本文数值作为原版规格。原版截图、录像和窗口证据只写入被忽略的 `artifacts/`。

## 版本、入口与状态

`GameState::new/with_clock` 保留空棋盘规则1.0及原有阳光命令消费者；新入口 `GameState::day(seed, initial, rules)` 验证纯数据 `SliceRules` 并创建规则2.0切片。`RulesVersion::current()` 为2.0，旧空棋盘摘要明确返回1.0。两者不兼容，当前没有持久回放消费者，不预建迁移器。正常应用使用seed7、关卡 `development-day-slice`、初始阳光150和开发规则；`--probe` 保留无原版资源的独立探针。

摘要包含当前关卡/时钟/阳光/RNG、初始seed/状态/时钟、完整规则、全部实体及其生命与下一动作tick、阳光过期tick、割草机状态、下一个ID、波次游标、天空阳光计时、两个卡片冷却计时、选择、暂停和胜负状态。实体ID从1开始，跨种类共享并按创建顺序递增；实体容器保持稳定顺序。重开恢复初始合同、RNG、ID和波次，不由app重建另一个世界。

## 输入与暂停重开因果

命令严格按提交顺序处理：选卡、种植、收集、铲除、暂停、恢复、重开。切片拒绝基础设施的 `AddSun/SpendSun`，正常app只发送游戏命令。种植依次检查格边界、占用、选卡、卡片冷却、余额；成功先扣费再产生种植事件，保留当前选卡。卡片冷却从命令执行时的当前tick计算。铲除不退款；收集删除一次阳光，同批重复收集报告缺失，余额溢出则保留阳光。

命令处理结束后，仅当本批没有重开、最终未暂停且局面仍运行，才推进一个tick与规则。推进时的事件外层为 `TickStarted`、本批有序命令事件、规则事件、`TickCompleted`；不推进时只返回命令事件。暂停命令后的游戏命令被拒绝，恢复命令后的命令继续生效；同批暂停→恢复会正常推进一次，暂停→种植→恢复的种植仍被拒绝。暂停冻结tick、实体、冷却、波次和随机数，仍接受恢复/重开。

重开前的命令先执行并保留事件，再恢复初始状态；重开后的命令在新局面执行。含任意重开的批次不推进tick，即使后续选卡/种植成功也保持初始tick。胜负后除了重开，所有命令均拒绝，空步不推进或生成实体。tick达到u64上限时，预计会推进的整个批次在任何修改之前panic并给出中文诊断；暂停/重开控制仍能处理，恢复若将导致推进则整批拒绝。计时加法饱和至上限，不发生整数环绕。

## 每tick阶段与碰撞

1. 阳光过期；本tick命令早于过期，所以可在过期tick推进前收集。
2. 按波次数组顺序生成所有到期僵尸。
3. 生成到期天空阳光。
4. 按植物创建顺序处理向日葵产阳光与豌豆发射。豌豆只对同排且中心在射手前方的存活僵尸开火；无目标不消耗发射机会。
5. 所有豌豆（包含本tick刚发射者）沿当前位置至新位置扫掠，与同排僵尸的水平区间相交时选择最靠左者，平局按ID。依次输出命中、伤害、死亡；死亡立即排除后续豌豆候选。超出棋盘右界的豌豆移除。
6. 存活僵尸向左扫掠，选择途中最靠右的存活植物；到达接触点后停止，按自身啃食计时输出伤害和植物移除。植物先开火/产阳光再可能在本tick被咬死。
7. 按行处理割草机：僵尸中心到达启动x即启动一次。运动割草机按僵尸/割草机相对旧新位置扫掠；启动当tick也清除触发线左侧的同排僵尸，避免高速跨越导致割草机漏救。割草机越过右界加半宽后永久耗尽。
8. 先检查存活僵尸是否突破失败x；否则波次全部生成且存活僵尸为空时胜利。终局不继续生成/移动实体。

碰撞均为开发的按行一维区间合同，不是对原版碰撞形状的测量结论。表现静态构图的外形不反向决定规则碰撞。规则坐标和UI命令不受视口、DPI或纹理尺寸影响。

## 登记资源构图与音效

资源读取沿用native/Web相同清单、大小、SHA-256及文本校验。源文件保持不改动。新增符号映射逐项用Reanim XML图像引用和manifest精确路径核对，再写成 `resources::IMAGE_MAPPING` 明确表，运行时不靠命名猜测。`properties/resources.xml` 的 `PROJECTILEPEA` 指向 `projectilepea`；实际登记输入为 `images/ProjectilePea.png`（28×28）。

| 表现对象 | 登记来源与选择 | 开发取舍 |
| --- | --- | --- |
| 向日葵 | `reanim/SunFlower.reanim`，`anim_idle`起始帧4 | 使用所有该帧可见图像，按源轨道顺序静态构图 |
| 豌豆射手 | `reanim/PeaShooter.reanim`，`anim_full_idle`为79..104，选择帧79 | 使用完整头/嘴/茎/叶静态构图 |
| 普通僵尸 | `reanim/Zombie.reanim`，`anim_walk`起始帧44 | 显式19条身体轨道白名单，排除旗手、门板、泳圈、胡须、路障、铁桶等附件 |
| 割草机 | `reanim/LawnMower.reanim`，帧0正常构图 | `anim_normal`无显式非负f，不能假装现有marker方法适用；使用登记帧0，隐藏tricked附件 |
| 阳光 | `reanim/Sun.reanim`，帧0 | 保持Sun3→Sun2→Sun1源层序、变换及透明度 |
| 豌豆 | `images/ProjectilePea.png` | 原始28×28图像以中心定位 |

僵尸白名单按源层序为：`anim_innerarm3`、`anim_innerarm2`、`anim_innerarm1`、`Zombie_neck`、`anim_head1`、`Zombie_innerleg_upper`、`Zombie_innerleg_lower`、`Zombie_innerleg_foot`、`Zombie_outerleg_upper`、`Zombie_outerleg_foot`、`Zombie_outerleg_lower`、`Zombie_body`、`Zombie_tie`、`anim_head2`、`anim_tongue`、`Zombie_outerarm_hand`、`Zombie_outerarm_upper`、`Zombie_outerarm_lower`、`anim_hair`。这只是已登记静态构图的显式选择，不是完整原版播放器附件语义。

核心状态生成实体画面；事件驱动中文即时反馈与音频：种植→`sounds/plant.ogg`，收集→`sounds/points.ogg`，豌豆命中→`sounds/splat.ogg`，割草机启动→`sounds/lawnmower.ogg`。这组音效对应关系属于开发选择，不声称原版触发一致。已有音乐/音频探针保留，实际音频设备与浏览器用户手势解锁须另行验收。缺失图像映射、构图轨道、登记文件、错误指纹或解码失败均显式失败，不回退占位。

当前六类对象是登记静态构图，会按模拟状态移动/生成/移除；尚未实现完整idle/射击/啃食/死亡动画混合与原版粒子。该差距属于表现验收未完成项，不能把静态资源加载成功称为完整原版表现还原。

## 自动验证与实际运行边界

core原创测试覆盖5×9、成本/冷却、边界/同格、扫掠最近目标与跨排隔离、重复收集/溢出/过期、植物死亡、一次割草机、胜负回放、输入次序、暂停/重开、时钟上限、初始合同及隐藏状态摘要。app无资源测试覆盖鼠标/触摸共用逻辑输入、选卡/铲除、事件到音效、构图层序及缺失轨道错误；登记集成测试核对六类构图和图像引用。固定seed/规模的Criterion切片场景不读取原版资源，创建和种植预热在计时外。

`--smoke 240 --slice-smoke --screenshot` 在隐藏窗口以每帧15模拟tick推进，脚本只发送正常选卡、种植、暂停/恢复和收集命令。截图写 `artifacts/vertical-slice/registered.png`，日志使用“切片冒烟事件”标识，与任务5视口证据分离。该脚本是开发实际运行工具，不提供正常游戏作弊按钮；日志必须确认种植、阳光、僵尸、豌豆和命中，不能只以退出码代表玩法通过。实际Windows/Web运行、独占基准、覆盖率与全workspace门槛由整合验收记录，本文不预先声称通过。
