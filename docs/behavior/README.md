# 行为测量与还原

参考文件身份见 [reference-baseline.md](reference-baseline.md)。原版行为测量尚未完成；`pvz-core` 已提供空棋盘规则1.0与白天可玩切片开发规则2.0。切片数值、阶段顺序、输入、静态资源构图及待验证项见 [开发切片合同](development-slice.md)，实际验证与暂停后的续做入口见 [切片阶段性结果](vertical-slice-results.md)。

## 当前模拟合同

`pvz-core` 使用显式 `SimulationClock` 推进 tick，默认的 60 tick/秒只是未完成原版时基测量前的开发参数。它用于可重复测试和性能基线，不代表原版规格。空棋盘保持原有阳光命令与事件顺序。切片摘要额外包含初始seed/状态/时钟、全部规则、实体、ID计数、波次、卡片计时、选择、暂停和终局；切片有序命令与规则阶段详见专题合同。

## 每条规则的记录要求

每个案例写清参考 ID、场景、输入、计时方式、重复次数、观察结果和结论可信度。
控制关卡、初始阳光、植物位置、僵尸种类、暂停状态等变量；随机相关行为需要多次重复，不能把一次出现的结果写成确定性规则。
计时记录墙钟时间与视频帧信息，注明录制帧率；不能把录制帧率直接解释成游戏模拟频率。

优先记录：模拟时基、种植/消失边界、阳光生成、发射与啃食间隔、投射物命中、减速/冻结、护甲层、波次触发、胜负与暂停。
每条数值必须带测量来源；攻略和其他实现只作线索，不能替代本机基线验证。

## 公共和私有证据

公开文档保留原创描述、测量表、资源清单引用和重写核心的逻辑回放。
版本化资源位于 `assets/original/`；原版截图、录屏、参考存档和测量结果保留在被忽略的 `artifacts/` 或仓库外，可重建的资源转换产物写入被忽略的 `target/`。
原版 EXE 与重写程序一般不会使用相同 RNG，故同一 seed 只能保证重写内部复现，不能自动要求两程序随机结果相同。

## 确定性回放

计划的回放记录包含 schema 版本、规则版本、参考 ID、模拟 tick 时长、RNG 算法与 seed、初始状态和带序号的 tick 输入。
比较状态摘要与事件顺序，不依赖纹理、声卡或实际窗口帧率。
发布版本改变规则、输入编码或 RNG 时升级回放版本，给旧回放明确的兼容或拒绝策略。
